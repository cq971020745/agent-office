# 材料再创作

先从当前用户有权的知识库中找到接近的材料和可引用事实，再以“推荐选项加自定义”的方式补齐要素，最后成稿。不要把一次开放式追问或直接出稿当作完整工作流。

## 引导流程

1. **识别与首检**：先确认写入的知识库工作目录；目录不存在时由用户确认后创建。再确认材料类型和初始主题，用 `knowledge_search` 检索类型、主题、代表性历史材料和可引素材。
2. **推荐模板**：展示 3 至 5 篇最接近的知识库材料，说明其匹配点。选项必须带 `documentId`，先问“是否以其中一篇作为结构或文风参考”，同时提供“自定义参考/不使用模板”。用户选定后调用 `knowledge_get_document` 读取全文或关键 chunk，不只依赖摘要。
3. **知识库驱动补项**：从命中资料生成可选项，逐轮收集材料类型、主题、依据素材、风格参考、使用场景/对象、篇幅或时长。每轮输出“推荐选项（可渲染为按钮）”与“自定义”，不要只抛开放填空。
4. **放行检查**：汇总已确认要素；缺项只问当前最影响成稿的项。用户要求立即出稿时，可基于已知内容继续，但列明假设与待核实项。
5. **成稿与闭环**：按用户选定的知识库模板、事实口径、文风画像和已确认目录成稿；用户明确不使用模板或知识库没有匹配材料时，才按材料类型组织通用结构。成稿后必须提供“继续修改”“文风校验”“上传知识库”三个方向；用户选择上传时进入下方上传确认，不得直接上传。

## 取材与事实闸门

- 用 `knowledge_search` 检索事实、目标、会议口径、进展和历史表述；涉及“最新/当前/上次”时单独检索日期和版本。
- 用户要求原句、全文或上下文时调用 `knowledge_get_document`。
- 只写可确认的内部事实。数据、节点、责任人或决策状态缺失时标为待核实；公开资料只作背景或对标。
- 引用使用 MCP 实际返回的标题、位置和链接。不要把相似材料当作本项目事实。

## 成稿规则

- 方案写清背景、问题、目标、任务、分工、节点、保障和风险。
- 汇报先结论，再写进展、成效、问题、原因、下一步和需协调事项。
- 讲话稿具有开场、认识、任务、落实和收束；避免口号，措施落到动作、对象、责任、时间或成果物。
- 正式材料稳健、具体、克制；区分已定、建议、待研究与草案，不擅自承诺“确保完成”。

默认输出“材料判断、核心口径、提纲或初稿、待核实清单”。本工作流不内置或展示本地模板；模板选择只来自用户可访问的知识库文档。

## 上传边界

仅当用户明确说“定稿或上传”时进入上传确认。上传确认必须按以下顺序完成：

1. **选择空间**：调用 `knowledge_list_spaces`，让用户从当前身份有权限的空间中单选；不要求用户填写或猜测空间 ID。
2. **展示并确认归属目录**：调用 `knowledge_list_directories(spaceId)` 获取目录树，用普通对话文本按缩进展示完整父子层级，不使用扁平 `AskUserQuestion` 选项让用户选目录。请用户用普通文本回复目录完整路径；如果只提供名称且存在同名目录，继续要求完整路径。目录是唯一业务归属，不创建独立事项实体，也不把目录选择混入标签多选。
3. **推荐并整理标签**：根据本次成稿内容、用户选定的参考文档和目录内已有文档，调用 `knowledge_list_documents` 或 `knowledge_search` 汇总已有 `tags`、`topics`，推荐 3 至 8 个相关标签。用户用普通文本补充或修改标签；标签去重后以字符串数组保存，不能把多个标签拼成一个字符串。
4. **回显与确认**：目录路径匹配成功后，用普通对话文本回显空间、目录完整路径、标题、已选标签（推荐/自定义来源）和文件路径；再使用 `AskUserQuestion` 仅询问“确认上传”或“修改”。用户选择“修改”时，只重做受影响的目录、标题或标签步骤；未确认不得写入。
5. **提交与回执**：用户确认后上传，随后调用 `knowledge_wait_document_ready(documentId)`。远程 MCP 使用 `knowledge_upload_document(spaceId, directoryId, fileName, contentBase64, title, tags)`；本机 stdio 可用 `filePath`。只有等待工具返回 `completed=true`、文档 `ingestStatus=READY` 且 `metadataSyncStatus=SYNCED`，才报告“已入库并完成同步”；失败或超时必须报告原因和文档 ID。
