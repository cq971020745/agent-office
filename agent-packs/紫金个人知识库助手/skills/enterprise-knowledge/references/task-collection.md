# 任务收发与材料收集

由 WorkBuddy 负责自动化调度、持久状态、循环与停止；由 WPS 365 负责通讯录、IM，以及「团队文档（紫金协作）」链路下的文件读写。「知识库」链路下，成员提交物由知识库 MCP（`knowledge_*`）列出和读取。不要把 WPS 的只读 `workflow` 轻审批技能误作自动化引擎。

进入本工作流且将使用 WPS 365 时，若本会话还没跑过 `wps365-env`，执行一次 `ensure`；通过后通讯录、IM、团队文档直接调用，不要每步再跑。

巡检查询位置按链路分开，不要混用：

- **团队文档（紫金协作）**：只查已确认的 WPS 团队文档库任务目录。
- **知识库**：只查成员被要求上传的那个知识库空间和目录。

**巡检汇报**和**材料汇总**不是同一件事。每轮巡检都按实际查到的提交情况做进度汇报。材料汇总只在发起人确认需要时才做；不是所有收集任务都要汇总。需要把汇总材料提交到知识库时，两条链路走同一套确认上传流程。

## 先选链路

进入收发场景后，**先**用 `askUserQuestion` 让收集者选择链路，再进入该链路的细化。未选定前，不查团队文档库、不展示知识库目录树、不生成派发预览。不要默认猜测链路，也不要把链路选项写进助手普通回复当按钮。

当前开放的选项：

- **团队文档（紫金协作）**：成员把材料交到 WPS 团队文档库任务目录。
- **知识库**：成员用电脑浏览器打开知识库，把材料上传到指定知识库目录。

不要自行增加未实现的通道。收集者已在原话中明确只要其中一条时，可跳过提问并复述确认后进入细化。

## 按链路细化

链路选定后，再确认该链路所需信息。能用 `askUserQuestion` 的平铺选择尽量用（任务要素推荐项、材料格式要求、重名成员、多条文档库命中、截止/催办策略、发送确认等）。**知识库目录树不能放进 `askUserQuestion`**：WorkBuddy 不支持树形选项，必须在助手回复正文里按缩进展示，请收集者用文本回复完整路径。

共用项：工作目录（知识库 `directoryId`，业务归属）、任务名称与目的、目标成员或部门、截止时间、文件类型、每位成员的唯一文件名规则、巡检间隔和提醒规则。

- 文件名规则必须含成员唯一标识，例如 `{任务简称}_{成员工号}_{YYYYMMDD}.docx`；只含姓名的规则在同名成员存在时不可用。
- 按“成员清单”而非群聊当前成员判定完成，清单在发起时由 WorkBuddy 保存。
- 未指定项时提供推荐选项和“自定义”；不要静默猜测目录、群聊或成员。

### 向发任务的人确认格式要求

生成派发预览前，必须向发任务的人确认本次收集材料的格式要求，并写入 WorkBuddy 任务状态，供后续收集完成后核对。不要跳过这一步。

**禁止为此新建核验口径文件。** 格式要求保存在任务状态里（文件类型、命名规则、模板文件 ID/文件名、必填章节或字段清单），不是再写一份《收集要求》或校验口径 Word/OTL 放到团队文档或知识库。只有发任务的人**已经提供**了现成的口径文件时，才 `drive get` 记下 ID/`link_url` 供巡检对照；没有现成文件就不要创建。

发任务的人原话已说清格式要求（例如指定了模板、必填章节/字段、文件类型）时，复述确认即可。未说清时用 `askUserQuestion` 询问，选项为：

- **有模板文件**：成员按模板填写。继续确认模板文件，保存 `file_id` 与文件名；发给成员时用 IM 本地文件发出去。
- **有内容结构或必填项**：由发任务的人口述或贴出必填章节/字段，写入任务状态。若对方已经提供了现成的《收集要求》口径文件，记下该文件供巡检对照，不要另写一份；口径文件不发给成员。成员需要遵守的填报规则写进消息正文。
- **只需文件类型和命名规则**：不启用正文内容核对，巡检只验文件类型和文件名。
- **暂无额外格式要求**：将正文核对标为未启用；后续不要补发明一套模板，也不要补建口径文件。

收集到材料后，只按任务状态里已确认的格式要求核对，不另加未确认的质量标准。

材料汇总默认不开启。收集者原话已明确要或不要时，复述确认即可。未说清时用 `askUserQuestion` 问「需要材料汇总 / 不需要汇总」，不要默认滚动汇总。只有选择需要时，再确认汇总口径；不需要汇总时，后续巡检只做查询、验收、催办和进度汇报。

### 团队文档（紫金协作）

再确认团队文档库与父目录。多条命中时用 `askUserQuestion` 让收集者选择，不得自行挑选。发给成员时：模板用 IM 本地文件发出去；提交目录附完整可点开 URL，禁止只写「团队文档 / 目录名」。填报规则写进消息正文。发起人已提供的《收集要求》或校验口径文件只留给数字员工巡检对照，不要发给成员，也不要在没有现成文件时新建一份。

### 知识库

再确认知识库空间和目录完整路径。对外发给成员的知识库入口**默认使用** `http://10.50.11.17/new-general-rag-kb/`，派发和催办消息都必须带上这个链接；不要改发 `/mcp-server`，不要带 `:5173`。收集者没有明确给出其他入口时，不要追问或替换该默认地址。页面不能直达某个目录，消息里仍须写清空间名称和目录完整路径。

1. 调用 `knowledge_list_spaces`。多个空间时用 `askUserQuestion` 平铺空间名称（不要展示空间 ID）。
2. 调用 `knowledge_list_directories`，在**助手回复正文**中按缩进展示完整目录树，保留父子层级；请收集者回复完整路径，例如 `检索验证-20260818/数智化专项`。同名目录必须继续要完整路径。禁止把目录树压成扁平 `askUserQuestion` 选项。选定后保存对应 `spaceId`（`sp_…`）与 `directoryId`（`dir_…`），后续调用必须原样回传，不要剥前缀、不要转成数字。
3. 向收集者确认目标成员已是该空间成员并可上传；MCP 不能代为加人。未授权时说明对方打开链接后无法上传。

## 建立任务

1. 确认业务任务写入的知识库 `directoryId`、目录路径、任务目标和输出物；如果目录不存在，先由用户确认后创建。知识库目录须已存在或由发起人在 Web UI 中创建；MCP 当前不能代建知识库目录。
2. 使用 WPS 365 `contacts` 查询指定成员或部门成员，保存 `user_id`、姓名与用于文件名校验的唯一标识。重名时用 `askUserQuestion` 选定。
3. 按已确认链路准备提交位置：
   - **团队文档（紫金协作）**：使用 `drive doclibs`、`list` 或 `search` 定位唯一的团队文档库和父目录；多条命中时用 `askUserQuestion`。将 `drive_id` 与 `parent_id` 作为任务状态必填字段，禁止使用 WPS 默认的个人云盘。用 `drive create <任务目录> --file-type folder --drive <drive_id> --parent-id <parent_id>` 创建任务目录；保存新目录 ID。确认所有目标成员已有该团队文档库的写入权限。定位到提交目录后执行 `drive get <folder_id>`，把完整 `link_url` 写入任务状态并写进发给成员的正文。`list` 的 Markdown 摘要通常不展示链接，必须读 JSON 的 `link_url`；`search` 可能只给相对路径 `/weboffice/fl/xxx`，须拼上当前环境的 `X_ORIGIN`（紫金私网为 `https://wps.zjholdings.cn`）。目录链接形如 `.../weboffice/fl/<link_id>`。同名嵌套目录必须取实际落点那一层的目录链接，不要只发父级路径。`link.status` 为 `closed` 时，团队库成员登录后仍可打开，不必默认 `file-open-link`；仅当收件人不是该库成员、需要库外访问时，才经确认后开启分享。若有模板文件：保存 `file_id` 与文件名；发给成员时不要发模板 URL，也不要发云文档卡片。正确做法是先 `drive download <template_file_id> --dir <临时目录>` 落到本地（这是发给 IM 的中间步骤，不要对成员走 download 的目录选择），再 `im upload <本地路径>` 取得 `storage_key`，再用 `im send --type file --file '{"type":"local","local":{"storage_key":"<storage_key>","size":<字节数>,"name":"<原文件名>"}}'` 发出去。若发起人已经提供《收集要求》或校验口径文件，`drive get` 后只写入任务状态供巡检对照，不要下载、不要当附件、也不要把该链接发给成员。没有现成口径文件时不要新建一份。
   - **知识库**：使用上文已确认的空间与目录完整路径。不创建 WPS 团队文档库任务目录。
4. 生成消息预览。若已要求按模板填写，预览中须写明将随消息发送模板原文件（文件名），以及提交目录完整 URL；不要把模板改成只发链接。发送确认用 `askUserQuestion`。发给成员的收集消息、催办和修正提醒，主体内容结束后必须空两行，再单独一行写 `——此条消息由agent发送`，不要贴在正文最后一行后面。发给发起人的巡检汇报、确认问答不要加这句。私网不要用 IM 云文档卡片（`type=cloud`）；模板走本地文件消息，提交目录走纯文本 `https://` 链接，长文用 `--text-file`。每位成员按「先文本、后模板文件」各发两条，两条都须取得当次确认后再 `--confirm`。
   - **团队文档（紫金协作）**：文本消息必须给出提交目录可点开链接和完整路径。推荐结构：先问候与任务名称；写「模板见下一条附件《文件名》」；再写「请提交到「目录名」：`<完整目录 URL>`」和完整路径（含嵌套，例如 `365wps测试团队 / 改革攻坚 / 改革攻坚 / 分台账`）、文件名示例、截止时间，以及成员需要遵守的填报规则（写进正文，不要改成「详见校验口径」）。禁止把《收集要求》或校验口径发给成员。禁止只写「请到团队文档某某目录下载模板」而不发模板文件、也不贴提交目录 URL。文本发出后，立即把已 `im upload` 的模板按本地文件发出去。
   - **知识库**：用友好口吻说明请对方用电脑浏览器打开知识库链接（不要用聊天附件或私聊交文件），进入指定空间和目录后再上传。消息必须包含默认入口 `http://10.50.11.17/new-general-rag-kb/`、空间名称、目录完整路径、文件名示例、截止时间；若发起人确认了成员需遵守的填报规则，写进正文，不要改成「详见校验口径」。不要在消息中写出空间 ID、目录 ID 或 MCP 地址。推荐结构：先问候与任务名称，再给出 `http://10.50.11.17/new-general-rag-kb/`，再写“打开后请进入「空间名 / 目录完整路径」上传”，再补文件名规则、填报规则（若有）和截止时间，最后空两行写 `——此条消息由agent发送`。
5. 按 WPS 365 规则先 dry-run，再取得本次发送（以及团队文档链路下的建目录、后续提醒，以及仅在启用材料汇总时的汇总写回）的明确授权，才用 `im send` 向个人或群聊发送。
6. 仅在已确认需要材料汇总时，才准备汇总落点。**团队文档（紫金协作）**首次创建汇总文档时优先使用 `.otl` 或 `.docx`。`.otl` 的后续更新用 `drive write`，禁止用二进制 `drive update` 覆盖。**知识库**链路不在 WPS 建汇总文档。未启用材料汇总时，不要创建汇总文档，也不要每轮生成汇总正文。
7. **必须调用 WorkBuddy 创建自动化任务。** 保存自动化任务 ID、业务任务 ID、链路方式、知识库 `directoryId`、目录路径、初始成员清单、巡检间隔、截止策略、提醒策略、是否启用材料汇总，以及本次可审计授权范围。团队文档链路另存 `drive_id`、父目录 ID、任务目录 ID，以及提交目录完整 `link_url`；启用汇总时再存汇总文件 ID。知识库链路另存空间名称，以及默认知识库入口 `http://10.50.11.17/new-general-rag-kb/`。任务状态还必须保存系统管理文件/文档 ID 集合、`accepted_file`、不合规提交指纹、下次提醒时间，以及后续可能写入的知识库原文件 ID。同时保存发任务的人已确认的格式要求：是否启用格式核对、文件类型、命名规则、模板文件 ID/文件名（若有）、口径文件 ID/完整 `link_url`（仅当发起人已提供现成口径文件时保存，仅供巡检对照，不发给成员；没有则不要创建）、必填章节或字段清单。发起人选择「只需文件类型和命名规则」或「暂无额外格式要求」时，将正文内容核对标为未启用，但仍保存文件类型与命名规则。催办未提交且派发时发过模板的，再按同一链路补发一次模板本地文件，并附提交目录链接。创建成功并返回首次巡检时间前，不得对用户回报“已完成派发收集”；创建失败时停止并说明原因。

   **专家绑定是必填项：** 创建自动化时必须把当前会话正在使用的专家标识一并写入 `expertId`，必要时同时写入 `expertMarketplace`；不得只保存 prompt、工作目录或 WPS 连接配置。这样自动化运行时才能重新加载当前专家及其随附 Skills（包括 `wps365-skill`、`pitfalls-and-experience` 和对应子 Skill）。创建后应通过自动化详情核对专家绑定已保存；若缺失，先暂停自动化并修复绑定，不得宣称自动化可执行。

WorkBuddy 注册自动化时必须保存可审计的任务授权范围。每次巡检的消息、提醒、创建和写回都只能在该范围内执行；若调度器不能将这项授权传递到 WPS 执行层，必须暂停并向发起人确认，不能因“自动化”绕过 WPS 365 的写入确认规则。

## 每次 WorkBuddy 巡检

先按链路查询，再验收，再催办，再按需汇总。查询位置不能串：团队文档只看任务目录，知识库只看成员上传的那个知识库目录。

1. 按链路列出成员提交物。排除汇总文档、状态清单和其他系统管理文件，不得将自动化产物视为成员提交。
   - **团队文档（紫金协作）**：用 `drive list --drive <drive_id> --parent <task_directory_id> --all` 列出任务目录全部文件；必要时用相同 `drive_id` 和目录范围 `search` 补检。不得只看首页或回退到个人云盘。
   - **知识库**：调用 `knowledge_list_documents`（限定已确认的 `spaceId` 与 `directoryId`，须为带前缀字符串 `sp_` / `dir_`，原样回传）列出该知识库目录文档；不得改扫其他空间、其他目录或团队文档库。读取正文用 `knowledge_get_document`。私聊/群聊附件不计入提交。
2. 分别保存两类命名状态，不用“最新任意文件”覆盖已验收结果：命名合规文件进入后续内容核对；`latest_invalid_attempt` 是最新命名不合规提交，只用于提醒。成员已有 `accepted_file` 后再次上传不合规文件，保留已验收状态；若启用了材料汇总，也保留原汇总来源，同时针对该新异常提交提醒。多份命名合规文件时取最后更新时间最新的一份，并在状态中留存其余版本。
3. 对命名合规文件按发任务的人已确认的格式要求核对。先核文件类型是否与约定一致。若启用了正文格式核对，再读取正文：团队文档用 `drive get-file-content --raw`；知识库用 `knowledge_get_document`。必须对照已保存口径核对（必填章节/字段是否齐全、是否仍为占位原文、结构是否与模板一致）；只按发起人确认的口径核对，不另加未确认的质量标准。命名合规、文件类型符合，且内容符合（或未启用正文核对）的文件才记为 `accepted_file`，用于完成判定；若启用了材料汇总，才作为汇总正文来源。命名合规但内容不符的记为内容异常，不计入完成。任何命名不合规、格式不符、内容异常或未提交成员都**不能阻塞**其他成员的验收；若启用了材料汇总，也不能阻塞对已合规材料的汇总。
4. **巡检汇报**每轮都做：按本轮实际查询结果，用 Markdown 表格向发起人回报进度，见「状态回报」。不要把进度表当成材料汇总。
5. **材料汇总**仅在任务已确认需要时才做；未启用则跳过本步，不要生成汇总文档或附当次汇总正文。启用后：把全部已合规材料综合成滚动汇总，并附“已合规、命名异常、内容不符合要求、未提交、未解析/读取失败”清单。已有合规文件必须进入汇总，不能等待全员提交；之后出现新的合规文件，或已有合规文件正文变化时，立即以最新合规材料集合更新同一份汇总。
   - **团队文档（紫金协作）**：只有合规材料集合或其内容变化时，才用 `drive write` 覆盖任务目录中的同一份汇总，避免无变化的重复写入。
   - **知识库**：在当次巡检回报中给出汇总正文；不每轮自动往知识库新上传一份汇总。

## 停止与异常

- 当发起时成员清单中的每位成员均有一份 `accepted_file` 时，停止本次定时巡检；停止即结束本次文件发现，不再因提交位置出现新文件、成员再次提交或新加入群聊而恢复任务。
- **未启用材料汇总**：任务至此完成。不要为了汇总去询问或上传知识库。知识库链路下成员原件已在指定目录中，无需再代传一份。
- **已启用材料汇总**：先写入最终汇总，再进入 `WAITING_FOR_KB_CONFIRMATION`。向发起人发送最终汇总（团队文档链路发汇总链接；知识库链路在当次回报中给出最终汇总正文），然后两条链路都用 `askUserQuestion` 询问“上传知识库 / 暂不上传 / 修改后再传”。未获明确选择前，禁止上传汇总。
- 发起人选择把汇总提交到知识库时，两条链路走同一套流程：确认知识库空间、目录、元数据和可审计写入授权后，用 `knowledge_upload_document` 上传最终汇总，并保存知识库原文件 ID。目录树在正文展示，`askUserQuestion` 只问确认/修改。知识库链路下成员原件已在指定目录中，这次上传的是系统汇总，不计入成员提交。若同一任务被发起人明确恢复，或发起人要求更新已发布汇总，且合规材料集合或内容指纹变化，必须更新该原文件 ID，不得再创建重复知识库文档；未恢复的已停止任务不自行继续巡检或写入。
- 截止时间到达但未全员合规时，按发起时确认的策略停止或继续；无策略时保留状态并向发起人报告，不自行无限循环。
- 不合规文件保留原文件，不擅自重命名、移动或删除；消息中指出预期文件名、提交位置（团队文档链路附提交目录完整 URL），以及内容缺口（若启用了格式核对）。知识库链路催办仍请对方用浏览器打开 `http://10.50.11.17/new-general-rag-kb/` 后改传到指定目录。
- 任务重试必须读取已有 WorkBuddy 状态和任务目录，禁止重复建目录、重复群发或将旧任务的文件混入新任务。
