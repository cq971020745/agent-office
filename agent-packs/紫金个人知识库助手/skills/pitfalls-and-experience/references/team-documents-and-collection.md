# WPS 365 团队文档与材料收集经验

## 1. 团队文档库成员不是 IM 群成员

- `contacts` 查部门或 `im list-members` 查会话，不能直接证明某人是团队文档库成员。
- 先用 `drive doclibs` 或 `drive doclib-meta` 获取文档库信息。
- 文档库 JSON 中的 `drive.allotee_id` 对应团队 `group_id`；需要核实成员时，通过团队成员接口查询 `group_id` 下的成员，`item_id` 为 `user_id`，`nickname` 为姓名，`role` 为 owner/normal。
- 创建目录前必须确认目标成员具备该团队文档库的写入权限；没有权限时，不能把“已发起收集”当作完成。

## 2. 正式材料收集的最小配置

发起材料收集前，**先**用 `askUserQuestion` 选择链路，再确认该链路要素：

- 任务名称和目标
- 目标成员清单及唯一 `user_id`
- 链路：`团队文档（紫金协作）` 或 `知识库`
- **团队文档（紫金协作）**：团队文档库 `drive_id`；任务目录 `parent_id`、目录 ID、目录路径，以及提交目录完整 `link_url`。若派发要求按模板填写，另存模板文件 ID 和文件名（发给成员用 IM 本地文件，不发模板 URL）。多条命中用 `askUserQuestion`。
- **知识库**：知识库空间名称、目录完整路径。发给成员的入口默认使用 `http://10.50.11.17/new-general-rag-kb/`（不要发 `/mcp-server`）；目标成员须已是该空间成员。目录树在助手正文按缩进展示，不要放进 `askUserQuestion`。
- 成员唯一文件名规则；优先包含工号，避免同名覆盖
- 文件类型
- 发任务的人确认的格式要求（模板、必填章节/字段，或明确只需文件类型和命名 / 暂无额外要求）；生成派发预览前必须确认，写入任务状态。不要为此新建《收集要求》或核验口径文件；只有发起人已提供现成口径文件时才记下其 ID/`link_url`
- 截止时间（使用带时区的 ISO 8601）
- 是否需要材料汇总；只有需要时才确认汇总口径，团队文档链路再保存汇总文件 ID
- 巡检间隔、催办规则和截止策略

## 3. 目录、链接与汇总文件

- **团队文档（紫金协作）**：使用指定团队文档库，不要回退到个人云盘。创建任务目录后保存 `drive_id`、`parent_id`、目录 ID 和链接状态。提交目录执行 `drive get` 取完整 `link_url`，写进派发/催办正文；禁止只写「团队文档 / 目录名」。模板不要发 URL，也不要发云文档卡片：先 `drive download <template_file_id> --dir <临时目录>`（发给 IM 的中间步骤，不要问成员保存到哪），再 `im upload` 取得 `storage_key`，再用 `im send --type file --file '{"type":"local","local":{...}}'` 作为下一条消息发出去。若发起人已经提供《收集要求》或校验口径文件，只 `drive get` 后保存供巡检对照，不要发给成员，也不要再另写一份；没有现成口径文件时，把必填项写入任务状态即可，禁止新建核验口径文件。成员需要遵守的填报规则写进消息正文。`list` 的 Markdown 摘要通常不展示链接，必须读 JSON；`search` 可能只返回 `/weboffice/fl/xxx`，须拼上 `X_ORIGIN`（紫金私网为 `https://wps.zjholdings.cn`）。目录用 `/weboffice/fl/`。同名嵌套目录要发实际落点那一层的目录链接。`link.status` 为 `closed` 时，团队库成员登录后仍可打开，不必默认 `file-open-link`；仅当收件人不是该库成员时，才确认分享范围后开启。只有发起人确认需要材料汇总时，才创建汇总文档：首次优先使用 `.otl` 或 `.docx`；`.otl` 后续使用 `drive write` 覆盖，不要使用二进制 `drive update`。
- **知识库**：不创建 WPS 任务目录。派发和催办消息默认发送 `http://10.50.11.17/new-general-rag-kb/`，并写清空间名称与目录完整路径；请对方用浏览器打开后再上传。页面不能直达目录，不要把 MCP 地址或空间/目录 ID 发给对方。未确认需要材料汇总时，不要每轮生成汇总正文。
- 发给成员的收集、催办、修正提醒：主体内容结束后空两行，最后一行写 `——此条消息由agent发送`。不要加在发给发起人的巡检汇报里。
- 需要把汇总提交到知识库时，两条链路走同一套确认上传：确认空间、目录、元数据和授权后再传，保存原文件 ID。

## 4. 巡检和验收

- 巡检查询位置按链路分开：团队文档只查任务目录，知识库只查成员上传的指定知识库目录。每次完整列出该位置，不要只看首页，也不要把汇总文档、状态清单或系统文件计作成员提交。私聊/群聊附件不算提交。
- 按成员清单判定完成，不按群聊当前成员判定。
- 合规文件和命名异常文件分开记录；已有合规文件不因后续异常提交而失效。
- 仅读取命名合规文件正文。按发任务的人已确认的格式要求核对：文件类型、模板结构、必填章节/字段。命名合规但内容不符的记为内容异常，不计入完成。发起人明确暂无额外格式要求时，不另加未确认的质量标准。
- **巡检汇报**每轮都做，默认用 Markdown 表格报告实际查到的进度：链路、查询位置、目标人数、已合规、命名异常、内容不符合要求（未启用则标「未要求」）、未提交、读取失败、材料汇总是否启用/更新、下一次巡检/停止原因。
- **材料汇总**按发起人实际需要启用，不是所有任务都要做。未启用时，命名异常、内容异常或未提交只影响进度汇报和催办。启用后，这些异常不能阻塞其他成员进入汇总。

## 5. 自动化闸门

- 必须先成功创建 WorkBuddy 自动化任务并取得自动化任务 ID、首次巡检时间和授权范围，才能向用户报告“已发起收集”。
- 自动化必须保存链路方式、目标成员、提交位置、截止时间、提醒规则、停止策略、是否启用材料汇总，以及发任务的人已确认的格式要求（是否启用正文核对、文件类型、命名规则、模板或内容验收口径）。启用汇总时再保存汇总口径；团队文档链路另存汇总文件 ID、提交目录完整 `link_url`、模板文件 ID 和文件名。口径文件完整 `link_url`（若有）只供巡检对照，不写入发给成员的催办。知识库链路另存空间名称、目录路径，以及默认入口 `http://10.50.11.17/new-general-rag-kb/`。
- 截止后按已确认策略停止或报告，不得无限循环。
- 任务重试时先读取已有状态和任务目录，禁止重复建目录、重复群发或混入旧任务文件。
