# 365WPS 踩坑与经验

## 私网 IM 不发送云文档卡片

适用范围：紫金私网环境（`PRIVATE=1`）下，通过 WPS 365 IM 向个人或群聊推送文档内容。

### 已验证限制

- `send_cloud_file` 被 SDK 标记为 `@private_unsupported`，仅公网支持。
- 通过 `messages/create` 发送 `type=cloud` 消息会报 `InvalidArgument: invalid file id or link id`。
- 即使云文档已经上传、分享链接已经开启，私网 IM 仍可能拒绝云文档/文件卡片消息。这是环境能力限制，不是简单的 file_id 或 link_id 参数错误。

### 默认处理方式

1. 先通过通讯录查询收件人唯一 `user_id`。
2. 长文本、讲话稿、材料正文或含特殊字符的内容，写入临时 Markdown 文件。
3. 使用 `im/run.py send --to-user <user_id> --text-file <path>` 发送 Markdown 文本消息本身。
4. 不要默认执行“上传云文档 → 开启分享 → 发送云文档链接”的流程。
5. 只有用户明确需要在线编辑或批注时，才说明私网限制，并改由用户选择公网或其他可用通道。

### 发送前检查

- 本会话第一次用 365 时若尚未检查环境，运行一次 `wps365-env` 的 `ensure`；通过后发送前不要再跑。缺 SID 或 401/403 时才 `ensure --refresh`。
- 发送操作仍须遵守 IM Skill 的 dry-run 与明确确认规则。
- 不要用测试消息探测通道；发送失败时报告真实错误并切换到文本消息路径。
