# 查询当前用户信息
用这个 skill 处理“当前登录用户是谁”以及“补齐当前登录用户详情”两类任务。

## 前置条件

- 已设置环境变量 `WPS_SID`
- 执行命令：把本 SKILL.md 绝对路径末尾 `SKILL.md` 换成 `run.py` 后直接 `python` 该路径（无需 cd）；须读同目录 `cli_reference.yaml`

## 快速使用

```bash
python skills/user-current/run.py me_base
python skills/user-current/run.py me
```

## 决策规则

- 用户只要确认“我是谁”“当前登录的是哪个账号”“我的用户 id 是什么”：
  执行 `me_base`
- 用户要获取当前账号的企业、邮箱、手机、登录方式、账号状态等基础字段：
  执行 `me_base`
- 用户要补齐当前登录用户的更详细资料：
  执行 `me`
- 用户要查“我属于哪个部门”这类更细信息：
  优先执行 `me`
- 当前上下文里已经有当前用户基础信息，但还缺补齐后的详情：
  执行 `me`
- 用户要查其他同事而不是当前登录账号：
  不要误用本 skill，应切到 `contacts`

## 子命令



- `me_base`
  用途：直接调用当前用户接口，返回当前登录账号基础信息
- `me`
  用途：先查询当前登录账号基础信息，再按当前姓名补齐更详细资料
  常用参数：`--page-size`

## 高风险操作

本 skill 均为只读查询；外发当前用户敏感字段前须 `askUserQuestion` 确认（见 `prompt_case` 安全用例）。

## 关键约束

- `me_base` 是稳定基础能力，只返回当前登录账号基础信息
- `me` 是复合工作流：
  先执行当前用户查询，再按当前姓名搜索通讯录详情，最后使用当前用户 `id` 精确过滤
- `me` 当前阶段通过“姓名召回候选 + 当前用户ID精确匹配”补齐详情，不是按用户 id 直接请求详情接口
- `TODO`：后续改为直接按用户 id 查询详情
- `me` 只有在候选结果中命中与当前用户 `id` 一致的记录时，才视为补齐成功
- 即使存在同名用户，也不能只按姓名命中结果自动选择
- 返回的用户 id 取自 JSON 里的 `id`
- 用户名称优先取 `user_name`，必要时回退到 `alias_name`、`nick_name`、`name`
- `phone` 可能是脱敏值，`email` 可能为空字符串
- `ctime`、`mtime` 在当前用户接口返回里是 Unix 秒级时间戳，不是 ISO 8601 字符串
- `def_dept_id` 不是可展示的部门名称；如果 `me` 没有成功补齐详情，不要根据它猜部门
- 需要确认脚本当前行为时，以 `python skills/user-current/run.py -h` 为准

## 输出格式

- `me_base`：输出当前登录用户基础信息摘要，再附完整 JSON
- `me`：输出当前登录用户基础信息摘要，再输出详情补齐结果，最后附组合后的 JSON

**`me_base` Markdown 示例：**

```markdown
## 当前用户基础信息

- **用户**：{user_name}
- **用户ID**：{id}
- **企业ID**：{company_id}
- **手机号**：{phone}
- **状态**：{status}
- **登录方式**：{login_mode}
```

**`me` 说明：**

- 当前阶段通过“当前姓名 -> 通讯录搜索 -> 当前用户ID精确过滤”补齐详情
- 只有命中与当前用户 `id` 一致的记录时，才返回补齐后的详情字段
- 如果只搜到同名用户但没有 `id` 精确命中，返回候选结果，不自动选人

需要确认脚本参数或帮助信息时，执行 `python skills/user-current/run.py -h`。

## 注意事项

- 不要把“当前用户”理解成“最近提到的那个用户”或“消息发送者之外的其他人”
- `me` 不是任意用户详情查询接口，只用于补齐当前登录用户信息
- 当前阶段姓名搜索只用于召回候选，最终必须通过当前用户 `id` 过滤
- 如果用户的问题其实是在补齐别人的用户 id 或资料，应切到 `contacts`

## 错误处理

- 若提示缺少 `WPS_SID`：请先设置环境变量后再调用
- 若返回 401/403：凭证无效或已过期，需重新获取 `WPS_SID`
- 若 `me` 未命中任何通讯录详情：保留基础信息，并明确说明“当前未补齐到详情”
- 若 `me` 只搜到同名候选但没有 `id` 精确命中：返回候选结果，不要擅自选择
- 若 `me` 命中多条同 `id` 候选：返回候选结果，不要擅自选择
